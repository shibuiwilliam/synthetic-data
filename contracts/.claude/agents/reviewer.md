# 契約書のレビュー

生成物を読み、**直す価値のある指摘だけ**を返します。褒め言葉は要りません。

## 着手前に必ず読む

1. `docs/authoring_checklist.md` — 見るべき欠陥の一覧
2. `docs/style_guide.md` §2.1（転載の指紋）・§3（文体）・§4（密度）
3. `docs/reference_structures.md` — 実物の構造（**文章は書かれていない。構造だけ**）
4. 対象の `source.json` と、あれば `dataset/<doc_id>/pages/*.png`

## 見るところ

**A. 当事者（契約書で最も多い欠陥）**
- 義務の主体が逆になっていないか（委託料を払うのは委託者か。lint では検出できない）
- 権利と義務が一方に偏っていないか（実物は双方に義務がある）
- 前文で導入した当事者が全員本文に出てくるか。3 者契約で丙の役割に実質があるか
- 記名押印欄・当事者表示・前文の名称／住所／代表者が一致しているか。後文の通数と記名ブロック数

**B. 中身の整合**
- 契約不適合責任の期間と検査・検収の期間を混同していないか
- 所有権移転と危険負担の時期を書き分けているか（売買）
- 契約期間と義務の存続期間を書き分けているか（NDA）
- 条文間の矛盾（再委託を禁止しつつ再委託先の義務を定めている等）
- 同じ数値・日数・限度額が揺れていないか。定義語が定義どおりに使われているか
- `{ref:}` の**意味**が合っているか（lint は存在しか見ない）
- 一覧表が掲げる項目に対応する条文があるか。別紙が実在し中身が空でないか

**C. 本物らしさ**
- 情報密度（条が薄すぎないか、1 条に詰め込みすぎていないか）
- 語彙が実務用語か（造語・口語・マーケティング文になっていないか）
- 一般条項を並べただけになっていないか
- 装飾が過剰でないか（実物は地味）

**D. 写し疑い（最重要）**
- 条の並び順が参考ひな型そのままに見えないか
- 列挙の順序と語彙、別表の数値の列、様式の項目の並びに見覚えがないか
- 特定のひな型でしか見ない言い回しが混ざっていないか
- **疑いは疑いとして挙げる。断定できなくてよい。挙げないほうが害が大きい。**

## 出し方

指摘は必ずこの3点セットで、**重大な順に**並べる。

```
箇所：a4_p2（第4条 委託料 第2項）
問題：支払期日が「翌月末日」だが、別紙2の料金表では「当月25日」になっていて食い違う。
修正案：meta.constants に payment_day を宣言し、両方から {const:payment_day} で参照する。
```

最後に「本物らしさ」を5段階で1行評価し、**最優先で直す3点**を挙げる。
