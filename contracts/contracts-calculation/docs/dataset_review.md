# dataset/ 全文・整合性レビュー（2026-10-05）

## 1. 対象と方法

`dataset/` の最終100文書（20 base、10 doctype、4 profile、seed 1〜6）を対象に、次を突き合わせた。

- ルート文書と `docs/` の設計・決定・レビュー記録を読み、CalcSpec を唯一の計算仕様として、契約文、
  正解プログラム、テストケースを同時生成する方針を確認した。
- 100件の `contract.json` と、その `calc/spec.json`、`answer_key.json`、`cases.jsonl`、`manifest.json`、
  HTML・PDFを全数走査した。契約本文では異なる text 文字列2,992種類と、当事者名41種類を確認した。
- 31生成パターンと4付与パターンの実装を文面・式・境界ケースの三方向から照合した。
- 親プロジェクトの名称 denylist（有効160項目）と既知衝突7項目を、JSON・JSONL・HTML・Markdown・
  text 全体に固定文字列で照合した。41当事者名は公開ウェブの完全一致検索も補助的に行った。
- challenge の意図的難所は通常の欠陥と分け、answer key と manifest のラベルを確認した。

## 2. 修正した事項

| 対象 | 発見した問題 | 修正 |
|---|---|---|
| K05 時間帯精算 | 稼働時間が著しく少ない境界ケースで、控除後の対価が負額になり得た | 計算式を `max(0, 控除前の額)` とし、「0円を下回るときは0円」の本文を追加 |
| K26 不可抗力通知 | 事由発生日前の通知も「期限内」と判定し得た | 発生日以後かつ期限内であることを判定条件に追加 |
| K10 価格改定 | 「公表される資材価格指数」だけでは採用指数が特定されず、指数の単位が「件」と表示された | 「個別契約に定める資材価格指数」に明確化し、単位を `INDEX` に修正 |
| K16 存続期間 | 応当日のない月の扱いが本文に無かった | その月の末日を応当日とする規定を追加 |
| K24 期限の利益喪失 | 「当事者は」の主体が双方とも喪失するようにも読めた | 「これに該当した当事者は」に明確化 |
| G3 上限例外 | 「故意のみ」を例外とする既存条項を、検査語が「故意または重過失」に限定していた | 故意のみの文型も検査できるよう修正 |
| G5 表示 | 計算例を持つ29文書でも「契約書面に計算例は無い」と表示した | 仕様内で検算した設例件数を表示 |
| v1 base 集合 | 親の content が増加中で、動的全件列挙が固定回帰の母集団を変えていた | HC-2 で決定した20件を `V1_BASE_CONTENT_IDS` として固定し、全件調査APIと分離 |

修正は生成パターン・検証器・設定の正本に入れ、生成物の個別手直しはしていない。生成器を0.8.3へ上げ、
同じ base・seed・profile の計画で100件を全量再生成した。

## 3. 意図的に残した難所

challenge 20文書のうち12文書には、評価目的のラベル付き難所がある（`anomaly` 5、`omission` 5、
`contradiction` 2）。これは不注意な矛盾ではなく、仕様発見能力を測る設計上のデータである。
answer key と manifest に対象ルール・種類・理由が明示され、両方の読みで正解が変わるケースは評価対象から
除外される。したがって通常文書の欠陥として除去しなかった。
