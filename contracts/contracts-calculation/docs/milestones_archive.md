## 4. MH5 — H5 カバー：apply 型 QA 47 問の機械検算

### 4.1 背景と方針

親の `HITL_TODO.md` H5 は「執筆 QA（`apply` 型）の算出値は L14 の包含検査の対象外で、**計算違いが機械で落ちない**。
計算の前提の置き方（起算日・端数処理・最悪ケースの採り方）そのものが判断の対象」として人間待ちになっている
（20 content・47 問。親の v1 タグの最後の 1 件）。

本サブプロジェクトの中核がまさにこの問題を解く：**各問の計算を CalcSpec として形式化し、
引用の逐語照合（G2 相当）・数値の往復（G4 相当）・明示性（G3 相当）を機械で検査したうえで、
参照インタプリタで答えを計算し、`qa_authored.json` の答えと突合する。**
前提の置き方は `obligations` として明示し、**本文に根拠のない前提だけ**を「読み幅あり」として人間に残す。
つまり「計算が合っているか」は全問機械で判定し、人間判断を「前提が本文から一義に決まらない問」に絞り込む。

これは付与モード（§6.1）の先行適用である。ただし汎用のバインディングは書かず、**1 問につき 1 仕様**を
`h5/specs/` に置く（仕様は人が書くが、引用・数値・答えの一致はすべて機械で検査するので、
「文言とプログラムを別々に書かない」原則には反しない——文言は親に既にあり、仕様が検査で文言に縛られる）。

4. 親側での決定の記入（HITL_TODO.md の「決定」欄）に必要な材料がそろっている。

### 4.3 注意

- 本サブプロジェクトは**親の HITL 判断を代行しない**。やるのは「機械側の確認」を計算の形式化まで深めることと、
  人間判断を要する問の範囲を根拠つきで絞ることである。
- (b)（演算不足）が出たら、CLAUDE.md「演算や型を足すとき」の手順（interp・validate・codegen・testgen・
  スキーマ・DESIGN.md §12 の同時修正）に従う。安易に演算を増やさず、まず既存演算への言い換えを検討する。
