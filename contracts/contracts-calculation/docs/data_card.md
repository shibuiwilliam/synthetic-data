# docs/data_card.md — データカード（`dataset/data-card.md`）の仕様・計画・タスク

> `dataset/data-card.md` は **計算条項データセットの利用者が最初に読む 1 枚**である。
> 「何が・どれだけ・どうやって作られ・何に使えて・何に使えないか」を**実測値だけ**で示す。
> **このファイル（`docs/`）が仕様の正本**で、`dataset/data-card.md` は
> `contracts-calc datacard update` が生成する**生成物**である（CLAUDE.md 規則2。手編集禁止）。
>
> - 版: 1.0（2026-10-04 新設）
> - 実装: `src/contracts_calculation/export/datacard.py`、CLI `datacard [update|check]`、
>   テスト `tests/test_datacard.py`、独立検算 `scripts/verify_data_card.py`
> - 親プロジェクトの同名文書（`../docs/data_card.md`）が設計の下敷き。**節の構成は踏襲し、
>   中身は「計算」のデータセット向けに置き換える**（親＝紙面と読み取りの素性、本サブ＝計算仕様と正解プログラムの素性）。

---

## 1. なぜ要るか（`dataset/README.md` との分担）

`dataset/README.md`（= `datasheet` の出力）は**パックの読み方と渡し方**を書く「使用説明書」である。
データカードは**データの素性**（規模・内訳・難易度の分布・作り方・品質保証・制限と偏り・ライセンス）を
書く「成分表示」で、読者も目的も違う。

| | `README.md`（datasheet） | `data-card.md`（データカード） |
|---|---|---|
| 読者 | これから評価コードを書く人・出題する人 | 使うかどうかを判断する人・引用する人 |
| 中身 | 文書数・パターン別件数・渡すもの／渡さないもの | 規模の実測・難易度の分布・生成方法・ゲートとオラクルの結果・制限と偏り・ライセンス |
| 重複の扱い | 渡し方は README が正本 | **カードは README を参照し、渡し方の表を再掲しない** |

**どちらも固定文字列に統計値を焼き込まない**（親 `docs/decisions.md` 105・131 と同じ再発防止）。

## 2. 絶対条件

1. **カードに出る数値はすべて `dataset/` の実ファイルから測る。** `DESIGN.md`・`TASK.md`・
   `CLAUDE.md`・過去セッションの記憶を数値の出典にしない。CLAUDE.md の「100 件・538 関数」等の
   記述は**要約であり出典ではない**。
2. **データを足したら更新される。** `generate` / `bind` / `datasheet` の出口で書き直し、
   忘れたら `datacard check` が落ちる（§5）。
3. **人間の判断が要る欄を AI が埋めない。** 配布条件は決定が無ければ「未決」と書き、`HITL.md` に起票する
   （CLAUDE.md 規則「迷ったら止めて質問する」）。
4. **母数の小さい観点を黙って隠さない。** 覆っている文書が閾値未満のパターン・難易度の軸は、
   カード自身が「この観点で精度を語るには母数が足りない」と明記する（§4.3）。
5. **生成は決定論。** 同じ `dataset/` なら同じカードが出る（生成日時・自分自身のファイルサイズを入れない）。
6. **実行時は標準ライブラリだけ**（CLAUDE.md 規則12）。PDF の実測は `re` ＋ `zlib`
   （オブジェクトストリームを解いて `/BaseFont`・`/Type /Page` を数える）で行い、外部ライブラリを入れない。

## 4. 実装の決め

### 4.1 測り方

- 入力は `dataset/`（= `--data` で与えたディレクトリ）配下だけ。`<cid>/calc/manifest.json` を持つ
  ディレクトリを 1 文書と数える。
- データは `dataclass` で持ち、裸の dict を回さない（CLAUDE.md コーディング規約）。
- **ページ数は PDF から実測**し、`_render/*/layout.json` の `page_count` と突き合わせる
  （食い違えば §6 に警告行を出す。黙って片方を載せない）。`_render/` が無い文書は PDF 側だけを使い、
  突合をスキップした旨を書く。
- 容量は拡張子ごとと**役割ごと**（評価対象に渡すもの／`calc/`／`_render/`／`_work/`）の 2 面で出す。
  **`data-card.md` 自身とドットファイル・`__pycache__` は数えない**
  （数えると書き出すたびに数が動き、鮮度検査が収束しない）。
- 数値の整形は `{:,}`。容量は MiB 小数 1 桁。

### 4.2 鮮度の守り方

カードは `dataset/` だけを見るので、README（datasheet）と違って「古い数字が残る」経路は
**カードを書き直さずに文書を足したとき**だけである。これを §5 の 3 重で塞ぐ。

### 4.3 母数の小さい観点の自動検出

次の観点について「それを含む**文書**の数」を数え、**閾値（既定 3 文書）未満**なら §11 に
「母数が足りない」として列挙する。観点を増やしたら自動で検査対象になる。

- パターン（宣言 31 種＋付与 4 種）
- 難易度の軸の値（`value_location`・`depth`・`calendar`・`condition`・`unknown`・`scatter`・
  `modality`・`priority`・`distractor`・`origin`）
- 表現手段（`modalities`）・値の在り処（`value_locations`）
- テストケースの種別と日付のタグ
- doctype・プロファイル・style・calc_seed

**宣言はあるが使っている文書が 0 のものは「未使用」として別に挙げる**（実装が検証されていない印）。
宣言の一覧は `patterns/registry.py`（31 種）・`bindings/engine.py`（4 種）・`config.py`（4 プロファイル）から取る。

### 4.4 人間の判断を待つ欄

- **配布条件**：未決。`HITL.md` に HC-3 として起票し、決定が入るまで「未決」と書く。
- フォントのライセンスは**実測した埋め込みフォント名から機械的に**引く（Noto → SIL OFL 1.1、
  IPAex → IPA FL v1.0）。埋め込みが無いフォントのライセンスを書かない。

## 5. 自動更新をどう担保するか（3 重）

| 層 | 仕組み | 効き方 |
|---|---|---|
| 生成 | `generate` / `bind` の 1 回の実行の最後に、出力先の README とカードを書き直す | 「足したら更新」が既定の流れに入る |
| 生成 | `datasheet` コマンドが README とカードを**対で**書き出す | 手で README だけ作り直す経路を塞ぐ |
| 検査 | `datacard check`（書き換えずに突合。終了コード 1）を `tests/test_datacard.py` と運用手順に入れる | 更新を忘れたら赤くなる |

**2 つの検査は別物である。**

| 検査 | 問い |
|---|---|
| `datacard check` | カードは**いまの `dataset/` から生成したもの**か（鮮度） |
| `scripts/verify_data_card.py` | **測り方そのもの**が正しいか（本実装を通さない別経路で再計算して突合） |

前者は常設（テストと運用手順）。後者は測り方を変えたとき（節や項目を足したとき）に手で回す。

## 7. 節を足すときの手順

1. 本ファイル §3 の表に行を足す（**何を・どこから測るか**を先に決める）。
2. `datacard.py` の `collect`（測る）と `render`（書く）の両方に足す。
   固定文に数値を書かない。母数の小さい観点になりうるなら §4.3 の対象に入れる。
3. `tests/test_datacard.py` に「その数値が実測から来ている」検査を足す
   （値を 1 つ変えたらカードが変わる、の形）。
4. `scripts/verify_data_card.py` に別経路の再計算を足し、手で 1 回回す。
5. 本ファイルの版を上げ、`docs/decisions.md` に 1 行足す。
