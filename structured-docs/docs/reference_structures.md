# reference_structures.md — 実在文書の構造分析の進め方

> 新ファミリー・新 doctype の構造設計、参考URLの取り扱い、`families/<f>/docs/structures.md` の執筆では、
> **着手前に必ず本ファイルを読む**こと。
> 先行例：yakkan-synth の `../insurance-contracts/docs/reference_structures.md`
> （A〜F 群のカタログ・分析ログの型はここに倣う）。

## 0. 転載禁止（最重要・CLAUDE.md §0.4-1）

- 実在文書・公開ひな型・書式集を読んでよいのは**構造・要素の種類・レイアウト慣行を把握するためだけ**。
- 文章は**メモにも残さない**。分析ログに書いてよいのは「第◯条相当に免責の列挙表がある」
  「禁止事項が 3 階層の入れ子リスト」のような構造記述のみ。例文が要るときはその場でオリジナルを作文する。
- 「ひな型だから著作権はない」と判断しない。判断に迷う素材は使わない。
- 法令の条文そのもの（e-Gov 等）は著作権の対象外だが、本プロジェクトの生成物には
  **法令名以外を引用しない**方針（CLAUDE.md §15）のため、構造把握の参考にとどめる。

## 1. 分析の手順（ファミリー追加・doctype 追加ごと）

1. 参考文書を 3〜8 件選ぶ（同種で発行元・体裁が異なるもの。URL と入手日を分析ログに記録）。
2. 次の観点で**構造だけ**を書き出す：
   - 前付け・後付け：表紙／目次／前文／当事者表示／署名欄／改定履歴／disclaimer の有無と位置
   - 階層と番号方式：何階層か、各階層のラベル書式、第1項無番号か、附則・別紙の独立体系
   - 表の類型：意味種別・結合セル・ヘッダ行列数・表下注記・繰返し表頭
   - 図の類型：フロー／ツリー／タイムライン／ステップ／マトリクス／模式図のどれに落ちるか
   - 参照と注：条項間参照の表記（「前条」「第◯条」「別紙◯」）、脚注・注記の流儀
   - ページ装飾：段組・ヘッダ/フッタ・ページ番号書式・見出し装飾・強調
   - 体裁レベル：素組み（白黒）〜装飾あり、のどの範囲を再現対象にするか
3. 書き出した特徴を「読み取り課題カタログ」（記号付き：契約書なら CT1, CT2, …）として
   `families/<f>/docs/structures.md` に整理し、各課題を blueprint の `required_elements` へ写像する。
4. カタログに現れた**コアで表現できない構造**があれば、`docs/schema.md` への提案として
   `docs/decisions.md` に起票する（勝手にコアを拡張しない）。

## 2. ファミリー横断で既知の課題群（コアが対応済みのもの）

yakkan-synth A〜F 群のうちドメイン非依存な課題はコアが継承済み：
階層見出しとラベル分離／文と一体の列挙表／但し書き／脚注・注記／結合セル表・繰返し表頭／
2段ヘッダ表／各種図／段組・ヘッダフッタ／定義語強調／ページ継続。
新ファミリーの分析では「これらのどれに当たるか」をまず当て、**当たらないものだけ**を新課題として起票する。

## 3. 本プロジェクトで新規に想定している課題（v1 設計の根拠）

| 記号 | 課題 | 対応 |
|---|---|---|
| G1 | 当事者表示と呼称の導入（「以下「甲」という。」）、以降の呼称参照 | `{party:}`（docs/schema.md §4） |
| G2 | 後文・日付・記名押印欄（欄の位置関係・「印」） | `signature`（docs/rendering.md §3.2） |
| G3 | 別紙（本文と別体系の番号・本文からの参照） | `schedule` |
| G4 | 附則（施行日・経過措置・改正履歴との共存） | `supplement` + `revision_history` |
| G5 | 深い入れ子リスト（禁止事項の 3 階層） | リスト機構＋要probe（docs/rendering.md §6） |
| G6 | 番号見出し流儀の揺れ（「第1条」型 vs 「1.」型） | numbering YAML の複数スキーム |
| G7 | 無ヘッダ・`- 1 -` 型フッタなど契約書特有のページ装飾 | style YAML |

## 4. 分析ログの型（`families/<f>/docs/structures.md` の末尾に追記）

```
## 分析ログ
### #1 2026-09-XX <文書の種類・発行元の種別（固有名は書かない方がよいが、URL は記録する）>
- URL / 入手日:
- 構造メモ: （箇条書き。文章の引用は一切しない）
- カタログへの反映: CT3 を新設 / G5 の実例
```

- 参考 URL は構造把握のためだけに開く。**取得した本文をリポジトリに保存しない**
  （スクリーンショットも保存しない。目視とメモのみ）。
