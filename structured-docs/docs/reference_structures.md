# reference_structures.md — 実在文書の構造分析の進め方

> 新ファミリー・新 doctype の構造設計、参考URLの取り扱い、`families/<f>/docs/structures.md` の執筆では、
> **着手前に必ず本ファイルを読む**こと。
> 先行例が 2 つある。**分析ログの型と課題カタログの書き方はこれに倣う**：
> `../insurance-contracts/docs/reference_structures.md`（A〜F 群・参考 14 件）と
> `../contracts/docs/reference_structures.md`（**CT1〜CT25**・契約書 36 種 39 ファイルを実測。
> 判型・ページ数の計測と目視を分けて記録し、§4.1 に「計測と見立ての食い違い」まで残している）。
> 分析道具 `scripts/analyze_reference_pdf.py`（構造だけを測り本文を一切出力しない）を移植して使う。

## 0. 転載禁止（最重要・CLAUDE.md §0.4-1）

- 実在文書・公開ひな型・書式集を読んでよいのは**構造・要素の種類・レイアウト慣行を把握するためだけ**。
- 文章は**メモにも残さない**。分析ログに書いてよいのは「第◯条相当に免責の列挙表がある」
  「禁止事項が 3 階層の入れ子リスト」のような構造記述のみ。例文が要るときはその場でオリジナルを作文する。
- 「ひな型だから著作権はない」と判断しない。判断に迷う素材は使わない。
- 法令の条文そのもの（e-Gov 等）は著作権の対象外だが、生成文書には**実在法令の名称以外を引用しない**
  方針（CLAUDE.md §15）のため、構造把握の参考にとどめる。statute ファミリーの生成文も
  同じ規約でオリジナルに書く（特定法令の定義列挙・数値基準・別表構成を写さない。
  `docs/families.md` §6）。
- **模倣は文章より「数値の列」「列挙の順序」「別表特有の語形」に出る**（yakkan の実証）。
  分析ログに数値の列を書き残さない。

## 1. 分析の手順（ファミリー追加・doctype 追加ごと）

1. 参考文書を 3〜8 件選ぶ（同種で発行元・体裁が異なるもの。URL と入手日を分析ログに記録）。
2. `analyze_reference_pdf.py` でページ数・判型・段組・記号の出現数・表の件数と列数・
   ヘッダ/フッタの有無を数え、代表ページを目視する。既知の計測の癖：
   - 段組の自動判定は幅広の表があると誤る。**段組は目視を正とする**。
   - 和文 PDF は `extract_text` が字間に空白を入れる。空白を潰してから数える。
   - MediaBox の原点が (0,0) でない PDF がある。ToUnicode の無いフォントはテキスト計測不能
     （その場合は目視のみを根拠と明記する）。
3. 次の観点で**構造だけ**を書き出す：
   - 前付け・後付け：表紙／目次／前文／当事者表示／署名欄／改定履歴／公布情報／disclaimer の有無と位置
   - 階層と番号方式：何階層か、各階層のラベル書式（漢数字・イロハ含む）、第1項無番号か、
     条見出しの位置（inline / above / plain）、附則・別紙の独立体系、枝番の有無
   - 表の類型：意味種別・結合セル・ヘッダ行列数・表下注記・繰返し表頭
   - 図の類型：フロー／ツリー／タイムライン／ステップ／マトリクス／模式図のどれに落ちるか
   - 参照と注：条項間参照の表記（「前条」「第◯条」「別紙◯」「（第◯条関係）」）、脚注・注記の流儀
   - ページ装飾：段組・ヘッダ/フッタ・ページ番号書式・見出し装飾・強調
   - 体裁レベル：素組み（白黒）〜装飾あり、のどの範囲を再現対象にするか
4. 書き出した特徴を「読み取り課題カタログ」（記号付き：契約書なら CT1, CT2, …）として
   `families/<f>/docs/structures.md` に整理し、各課題を blueprint の `required_elements` へ写像する。
   **必須要素は構造で縛り、semantic_type で題材を縛らない**（yakkan D4 の教訓）。
5. カタログに現れた**コアで表現できない構造**があれば、`docs/schema.md` への提案として
   `docs/decisions.md` に起票する（勝手にコアを拡張しない）。
   **正解が作れない体裁は再現対象にしない**（yakkan：縦組み見出し・ルビは実測のうえ不採用）。

## 2. ファミリー横断で既知の課題群（コアが対応済みのもの）

**姉妹 2 本のカタログのうちドメイン非依存な課題はコアが継承済み**なので、新ファミリーの分析では
「これらのどれに当たるか」をまず当て、**当たらないものだけ**を新課題として起票する。

- yakkan A〜F 群：階層見出しとラベル分離／文と一体の列挙表／但し書き／脚注・注記（条末 (*n)・
  備考枠 ❶）／結合セル表・繰返し表頭／2 段ヘッダ表／各種図／段組・ヘッダフッタ／定義語強調／
  見出しバッジ／条見出しの体裁 3 種／表番号の階層採番／ページ継続。
- keiyaku CT1〜CT25（契約書 39 ファイルの実測）：**骨格 5 類型**（条文型・頭書型・様式型・約款型・
  逐条解説型）／頭書と本文の対応／記名押印欄と収入印紙欄／条の通し番号／第1項に番号を振る流儀と
  振らない流儀／号の括弧の全角半角の割れ／漢数字の条番号（約款型）／条見出しが条番号の上／
  基本契約と個別契約（様式）／選択欄（「該当を〇で囲む」「有・無の一方を囲む」が実物では主流で、
  `□` のチェックボックスは少数）／A3 縦の官公庁様式。
  **移植先は `families/contract/docs/structures.md`**（P3。本文は写さず構造記述と URL・入手日だけ）。

## 3. 本プロジェクトで新規に想定している課題（v1 設計の根拠）

**「実証」列は 2026-10-05 時点**。✓ は姉妹の実装・実測で成立が確認できているもの、
**未** は本プロジェクトで初めてやるもの（＝probe と設計確定が必要なもの）。

| 記号 | 課題 | 対応 | 実証 |
|---|---|---|---|
| G1 | 当事者表示と呼称の導入（「以下「甲」という。」）、以降の呼称参照 | `{party:}`（docs/schema.md §4） | ✓ keiyaku（100 文書） |
| G2 | 後文・日付・記名押印欄（欄の位置関係・「印」） | `signature`（docs/rendering.md §4.2） | ✓ keiyaku（probe 実測：丸枠 34.8pt・horizontal の読み順） |
| G3 | 別紙（本文と別体系の番号・本文からの参照） | `schedule` | ✓ keiyaku（別紙・別表・様式の 3 系統） |
| G4 | 附則（施行日・経過措置・改正履歴との共存・多層化） | `supplement` + `revision_history` | ✓ yakkan（附則）／改正履歴は keiyaku |
| G5 | 深い入れ子リスト（禁止事項の 3 階層） | リスト機構＋要probe（docs/rendering.md §7） | **未**（terms。P4 冒頭で probe） |
| G6 | 番号見出し流儀の揺れ（「第1条」型 vs 「1.」型） | numbering YAML の複数スキーム | ✓ keiyaku（standard / form / kanji の 3 方式） |
| G7 | 無ヘッダ・`- 1 -` 型フッタなど契約書特有のページ装飾 | style YAML（page_number: dashed は移植済み） | ✓ keiyaku（無ヘッダ・`- 1 -` 型フッタ） |
| G8 | 漢数字カウンタ（第十二条）とイロハ細目 | counter `kanji` / `iroha`（docs/schema.md §7） | 漢数字は ✓ keiyaku（`contract-kanji`）／**イロハは未** |
| G9 | 条の枝番（第二条の二） | `number_override`（＋reason。docs/schema.md §11.2） | **未**（statute。P6） |
| G10 | 目次の条範囲（「（第一条―第五条）」） | `derived.toc[].article_range`（docs/schema.md §11.2） | **未**（statute。P6） |
| G11 | 別表の関係条注記（「別表第一（第三条関係）」） | `Node.relation_refs`（docs/schema.md §11.3） | **未**（statute。P6） |
| G12 | 公布情報（法令番号・公布日・公布文） | `meta.promulgation`（docs/schema.md §11.1） | **未**（statute。P6） |
| G13 | 読替え表（準用の「…と読み替えるものとする」の表化） | semantic_type `reading_replacement` | **未**（statute。P6） |

## 4. 分析ログの型（`families/<f>/docs/structures.md` の末尾に追記）

```
## 分析ログ
### #1 2026-09-XX <文書の種類・発行元の種別（固有名は書かない方がよいが、URL は記録する）>
- URL / 入手日:
- 構造メモ: （箇条書き。文章の引用は一切しない）
- カタログへの反映: CT3 を新設 / G5 の実例
```

- 参考 URL は構造把握のためだけに開く。**取得した本文をリポジトリに保存しない**
  （スクリーンショットも保存しない。目視とメモのみ）。
