# data_card.md — データカード（`dataset/data-card.md`）の仕様と自動更新

> データカードの生成（`docsynth/datacard.py`）・節の追加・測り方を触る作業では、
> **着手前に必ず本ファイルを読む**こと。
> 基底：`../contracts/docs/data_card.md`（keiyaku 実装の正本）＋`../insurance-contracts/docs/data_card.md`。
>
> - 版: 1.0（2026-10-05 新設。`docs/decisions.md` 2026-10-05）

## 1. なぜ要るか（`dataset/README.md` との分担）

`dataset/README.md` は**ファイルの読み方**（どの成果物に何が入っているか・座標系・注意点）を書く
「使用説明書」である。これに対しデータカードは**データの素性**（規模・構成・作り方・品質保証・
制限・偏り・ライセンス）を書く「成分表示」で、読者も目的も違う。

| | `README.md` | `data-card.md` |
|---|---|---|
| 読者 | これから評価コードを書く人 | 使うかどうかを判断する人・引用する人 |
| 中身 | ファイル構成・スキーマ・座標系・採点コマンド | 規模の実測・内訳・生成方法・検証の結果・制限と偏り・ライセンス |
| 重複の扱い | ファイル構成は README が正本 | **カードは README を参照し、構成の表を再掲しない** |

**どちらも固定文字列に統計値を焼き込まない。** 両姉妹で実際に事故が起きている
（yakkan：仕様書に「クエリ 778」と書いてあったが実測 1,170。keiyaku：`dataset/README.md` の
生成ロジックが統計値を固定文字列で焼き込んでいた）。

## 2. 絶対条件

1. **カードに出る数値はすべて `dataset/` の実ファイルから測る。** 仕様書・計画書・
   過去のセッションの記憶を数値の出典にしない（CLAUDE.md §2-7）。
2. **文書を足したら更新される。** 更新しないままデータが増えたら `make check` が赤くなる（§5）。
3. **人間の判断が要る欄を AI が埋めない。** ライセンス・配布条件は決定が無ければ「未決」と書き、
   `HITL_TODO.md` に起票する（CLAUDE.md §0.2-1。本プロジェクトでは D2・D3）。
4. **母数の小さい観点を黙って隠さない。** 1〜2 content しか覆っていない観点は、カード自身が
   「この観点で精度を語るには母数が足りない」と明記する（§4.3）。
5. 生成は決定論。同じ `dataset/` なら同じカードが出る（**自分自身のファイルサイズは数えない**。§4.1）。
6. **ファミリー横断の偏りを明示する。** 本プロジェクトは 5 ファミリーを 1 データセットにまとめるので、
   「どのファミリーが何文書か」「観点がどのファミリーに偏っているか」が最重要の素性になる。

## 3. 構成（節と、各節の数値の出所）

| 節 | 中身 | 数値の出所 |
|---|---|---|
| 1 概要 | 一行説明・版（`dataset_version`）。**生成日時は書かない**（決定論。CLAUDE.md §13） | 固定文＋`manifest.json` |
| 2 想定する用途／想定しない用途 | 読み取り・レイアウト頑健性・構造抽出・検索の評価。**実務利用と法的利用は対象外** | 固定文 |
| 3 規模 | 文書・content・**ファミリー**・doctype・style・ページ・文字・QA・要素・パッセージ・容量 | `manifest.json`・`elements.jsonl`・ファイルサイズ |
| 4 内訳 | **ファミリー別**／doctype 別／style 別（実測フォントつき）／文書別（全件）の表と、**骨格・体裁の覆い**（条文型・頭書型・様式型・約款型・逐条解説・章立て・目次・附則ほか） | `manifest.json`＋`source.json`＋`doc.pdf` |
| 5 正解の中身 | 構造（ノード種別）・表（意味種別・セル数）・図（種別・ノード・辺・経路）・参照・定義語・当事者・QA（種別／出所／答えの型） | `source.json` の `derived`＋本体、`qa.json` |
| 6 版面 | 判型・段数・領域別の行数・renderer と版・PNG の dpi・**PDF に実際に埋め込まれていたフォント**（`layout.renderer.fonts` は描画に登録した候補で、使われたものとは違う） | `layout.json` ＋ `doc.pdf`（pdfplumber で実測） |
| 7 検索評価セット | パッセージ（種別別）・クエリ（**10 種別ごと**）・qrels（grade 別）・打ち切りクエリ・**弁別力の実測**（素朴な検索器 3 系統。`docs/evaluation.md` §7.2）と「飽和」の印 | `dataset/search/*.jsonl` ＋ 弁別力レポート |
| 8 生成方法 | JSON→HTML→PDF・決定論・seed・執筆の役割分担・**外部 LLM API を使わないこと** | 固定文＋`layout.json` の renderer |
| 9 架空性と転載 | ハードルール（架空・転載禁止・法令の条番号を書かない）・奥付の disclaimer・**参考文書をリポジトリに置かないこと** | 固定文＋`source.json` の `meta.disclaimer` |
| 10 品質保証 | lint（L00–L26）・verify（V01–V11 ＋ V-P1〜V-P5）・検索の自己検査（V-S1〜V-S9）・`manifest check`・`eval --all --oracle`・検証の階段 V-A〜V-F の到達段 | 固定文＋`manifest.json` の `status` |
| 11 制限と既知の偏り | 日本語横書き・スキャン劣化なし・印影なし等（固定）＋**母数の小さい観点の自動検出**（§4.3）＋**ファミリー間の不均衡** | 固定文＋実測 |
| 12 ライセンスと配布 | 生成物の扱い（**未決なら「未決」と書く**）・**実測した埋め込みフォント**のライセンス（Noto → SIL OFL 1.1／IPAex → IPA FL v1.0）・同梱しているが使われていないフォント・`render.html` は配布対象外 | 固定文＋§6 の実測＋`docs/distribution.md` |
| 13 更新のしかた | 生成物であること・`docsynth datacard update`・鮮度検査 | 固定文 |

## 4. 実装の決め

### 4.1 測り方

- 入力は `dataset/` 配下だけ。`manifest.json` は `docsynth.manifest.Manifest`、`source.json` は
  `docsynth.models.Source`、`layout.json` は `Layout` で**モデルとして読む**（CLAUDE.md §13
  「dict を裸で回さない」）。
- 容量は `dataset/` の全ファイルを拡張子ごとに合計する。**`data-card.md` 自身は数えない**
  （数えると書き出すたびに数が動き、鮮度検査が収束しない）。ドットファイルも数えない。
- 数値の整形は `{:,}`。容量は MiB 小数 1 桁。
- **`datetime.now()` を入れない**（決定論）。

### 4.2 検索評価セットの鮮度

`search/` は `docsynth export` の出力なので、文書を足して export を回していないと
**カードの検索の数だけが古い**という状態が起こりうる。カードは `search/passages.jsonl` に出てくる
`content_id` と `dataset/` の content を突き合わせ、欠けているものがあれば §7 に**警告行を出す**
（黙って古い数を載せない）。

### 4.3 母数の小さい観点の自動検出

次の観点について「それを含む content の数」を数え、**閾値（既定 3 content）未満**なら §11 に
「母数が足りない」として列挙する。**観点を増やしたら自動で検査対象になる**ように、
観点の一覧はデータ（レジストリ）として持つ。

- ファミリー・doctype・numbering scheme・style・`digit_style`・`article_heading`・`caption_numbering`
- 骨格・体裁：`head_matter`・目次・`commentary`・脚注・当事者 3 者以上・章立て・附則・`number_override`・
  `rider`・`badges`・**条文型／様式型**
  （**`kind: "article"` の有無では分かれない**——様式型も `article` ノードを使い、番号方式が
  「（１）」と振るだけである。**条ラベルの形**（`第◯条` か）で見る。keiyaku decisions 141）
- 要素：表の意味種別・図の種別（6 種）・数式・結合セル・欄外注・読替え表
- 検索：クエリ 10 種それぞれの件数（0 件の kind は「未生成」として挙げる）

**使っていない宣言（content が 0 のもの）は「未使用」として別に挙げる**
（keiyaku では `ct-a3-landscape-form` が実装済みで使用 0 のまま残っていた）。

## 5. 自動更新をどう担保するか（3 重）

| 層 | 仕組み | 効き方 |
|---|---|---|
| 生成 | `docsynth export` の最後に `write_card()` を呼ぶ | 既存の「足したら export」の流れで更新される |
| 生成 | `make batch`（`docsynth batch` → `manifest update` → **`datacard update`**） | バッチで足したら更新される |
| 検査 | **`make check` に `datacard-check` を足す** | 更新を忘れたらコミット前に赤くなる |

`docsynth datacard check` は `manifest check` と同じ流儀で、**書き換えずに**食い違いを報告する
（終了コード 1）。`dataset/` が無ければ飛ばす。

**2 つの検査は別物である。**

| 検査 | 問い |
|---|---|
| `docsynth datacard check` | カードは**いまの `dataset/` から生成したもの**か（鮮度） |
| `scripts/verify_data_card.py` | **測り方そのもの**が正しいか（pydantic を通さない別経路で再計算して突合） |

前者は `make check` に入っている。後者は測り方を変えたとき（節や項目を足したとき）に手で回す。

## 6. 変えるときの注意

- 節を足したら §3 の表と `scripts/verify_data_card.py` を同時に更新する。
- **統計値を文章の中に書かない**（「約 60 文書」のような丸めも書かない）。表に実測値を置き、
  文章はその表を指す。
- ライセンス・配布の欄は `docs/distribution.md` と `HITL_TODO.md` の決定を転記するだけにする
  （カードが一次情報にならないようにする）。
