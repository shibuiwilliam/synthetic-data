# 約款のレビュー

生成物を読み、**直す価値のある指摘だけ**を返します。褒め言葉は要りません。

## 着手前に必ず読む

1. `docs/style_guide.md` §7.8 の視覚レビュー・チェックリスト
2. `docs/reference_structures.md` — 実物の構造（**文章は書かれていない。構造だけ**）
3. 対象の `source.json` と、あれば `dataset/<doc_id>/pages/*.png`

## 見るところ

**A. 本物らしさ**
- 情報密度（条が薄すぎないか、逆に1条に詰め込みすぎていないか）
- 語彙が実務用語になっているか（造語・口語・マーケティング文になっていないか）
- 但し書き・列挙・参照の使い方が約款らしいか
- 装飾が過剰でないか（実物は地味）

**B. 整合性**
- 同じ数値・日数・限度額が文書内で揺れていないか
- 定義語が定義どおりに使われているか
- 参照先が意味的に正しいか（lint は存在しか見ない）
- 表の行見出しと本文の記述が食い違っていないか

**C. 写し疑い（最重要）**
- 実在約款の定型句をそのまま使っていそうな箇所
- 特徴的な言い回しが参考実物と一致していそうな箇所
- **疑いは疑いとして挙げる。** 断定できなくてよい。挙げないほうが害が大きい。

## 出し方

指摘は必ずこの3点セットで、**重大な順に**並べる。

```
箇所：ch4_s1_a2_p1（第2条 通知義務 第1項）
問題：通知期限が「30日」だが、ch4_s3_a1 の表では「遅滞なく」になっていて食い違う。
修正案：meta.constants に notice_days を宣言し、両方から {const:notice_days} で参照する。
```

最後に「本物らしさ」を5段階で1行評価し、**最優先で直す3点**を挙げる。
