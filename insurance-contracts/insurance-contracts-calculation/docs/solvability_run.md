## この測定が示すこと／示さないこと

**示すこと**：出題（約款の該当箇所＋引数の定義＋呼び出しの取り決め）だけを与えられた解き手が、
約款を読んで計算規定を実装できるか。できなければ、約款の書き方か出題の作り方に穴がある。

**示さないこと**：
- **生成側と解き手が同じモデルである**（H5 (a) の既知の懸念）。「このモデルには解ける」ことしか
  示さない。別のモデルや人が解けるかは測っていない。
- 解き手には「課題文の 1 ファイル以外を読まないこと」を指示したが、**守ったことを機械的には
  検証していない**（ツール使用は各 1〜2 回で、正解ファイルを開いた形跡はない）。
- **種目ごとに 1 文書だけ**である（`auto` は 5 文書）。40 文書すべてでは測っていない。

## 手順

```bash
cd insurance-contracts-calculation
export DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib
# 1. 出題を作る（H2 ヒント＝根拠の条文つき）。**ファイルに落として解き手に読ませる**

open('prompt.md','w').write(solvability.prompt_for('out/v1/auto-0001-c1'))"
# 2. 解き手に prompt.md を読ませ、返った Python を submission.py に保存する
# 3. 採点する
PYTHONPATH=src python -c "
import pathlib, tempfile
from insurance_contracts_calculation.verify import solvability
src = pathlib.Path('submission.py').read_text(encoding='utf-8')
with tempfile.TemporaryDirectory() as t:
    print(solvability.check(pathlib.Path('out/v1/auto-0001-c1'), lambda _p: src, pathlib.Path(t)))"
```

> 解き手が**別の問題**を解いた。その測定は破棄した。人の転記を経路に入れてはいけない。

## 見つけた不備（すべて生成側を直した。期待値と約款の文言は変えていない）

| # | 不備 | なぜ致命的か | 直し方 |
|---|---|---|---|
| 1 | **タスクカードに `{term:insured_car}` が残っていた** | 入力の説明文は `{t:車}` → `{term:insured_car}` の形で作られる。約款本文なら本体の build が解決するが、**`spec.json` と `tasks.jsonl` は RichText ではない**ので誰も解決しない。表示が壊れるだけでなく**内部IDが漏れる**（`CLAUDE.md` 守ること 4）。`icc eval` の利用者にも同じものが渡っていた | `generate._resolve_input_descs()` が `doc.resolve()` で解決する |
| 2 | **明細（`list[dict]`）の辞書の項目名を出題に書いていなかった** | 「明細の並び（1 件ごとに次の項目を持つ辞書）」とだけ書いて項目名 `item_loss` を書いていない。解き手は `item_loss` を直接の引数と読み、**12 ケースすべてが `TypeError`** になった。タスクカード自身は `fields` を持っていたので、出題の組み立てだけの落ち | `solvability.prompt_for()` が `fields` を展開する |
| 3 | **取り決めが 2 か所に別々に書かれていた** | `taskcards.CONVENTIONS` と `solvability.prompt_for()` の文が**実際にずれていた** | `prompt_for()` が `CONVENTIONS` を引く（単一の正） |
| 4 | **三値の取り決めに裏側が書いていなかった** | 「確定できないときは `None`」だけで、**確定するなら確定した値を返す**を書いていない。解き手は「`None` が 1 つでもあれば `None`」と読み、7 件を落とした | `CONVENTIONS["unknown"]` に裏側を明記 |
| 5 | **裏側を足したら、今度は計算にも広がった** | 「ほかの入力で確定するなら確定値」と書いたため、解き手が**算術にも**determinacy を適用し、「経過月数は 0 か 1 のどちらでも割合は同じだから確定」と推論して 3 件外した。`spec/interp.py` は **`and`/`or`/`if` だけ Kleene の三値、算術・比較・表引き・日付は厳密**である | 取り決めの文をその区別どおりに書き直した |

**4 と 5 は約款の文言の問題ではなく、こちらの取り決めの書き方の問題**である。
`CLAUDE.md` 守ること 8（一義に読める文言だけを出す）に従って直した。
**期待値は 1 つも書き換えていない**（守ること 9）。**約款の文言も直していない**（`PROMPT.md` §P-S4）。

### 疑って見たが、正しかったもの

## ここから分かる、このデータセットの難所

- **三値論理が最大の難所である。** 2 回目の不合格 7 件すべてがこの型だった。
  読み取りの評価としては「約款を読めたか」より「三値の取り決めを守れたか」を測る面がある。
  不明値ケースを母数に含めるかは `HITL.md` H2 で「含める」と決まっており、`kind` で切り離せる。
- **明細（`list[dict]`）の渡し方は、約款の文言とは別に説明が要る。** 約款に「1 件ごとの損害の額」と
  書いてあっても、プログラムの引数が「辞書の並び」であることは約款からは読めない。
