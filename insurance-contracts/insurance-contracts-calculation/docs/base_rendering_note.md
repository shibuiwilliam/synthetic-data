- 日付: 2026-10-03
- 影響: 生成した文書の一部が検証ゲート G9c（本体 `verify_dataset`）で落ちる
- **状態: 直した（2026-10-03・S10-2）。** `HITL.md` H6 (c) で人が承認したので本体を変更した。
  `styles/css/_base.css.j2` の `.footnotes .fn-line` に **`break-inside: avoid`** を足した。
  本体 `docs/decisions.md` に記録済み

## 現象

既定の約款に**どんな内容でも少し足すと**、既定の約款にもともとある脚注が
PDF のテキスト層から消えることがある。本体の `verify_dataset` は V03（往復一致）で検出する。

```
[error] V03 <fn_ch4_s2_a2__n1: 短期率は、保険期間が１年に満たないご契約にも適用します。>:
        PDF から読み出せない期待テキストが 2 件
[error] V03 <box側 '短期率は、保険期間が１年に満たないご契約にも適用しま' / PDF側 ''（位置 784）>:
        p10: box ツリーのテキストが PDF と一致しない
```

## 切り分け

`auto-0006` に、図も表も囲みも持たない**ただの 1 段落**を足して長さを変えた。

| 足した字数 | ページ | verify のエラー |
|---|---|---|
| 0（既定のまま） | 14 | 0 件 |
| 120 | 14 | **3 件**（脚注 2 本が PDF に出ない） |
| 400 | 14 | 0 件 |
| 800 | 15 | 0 件 |

脚注の bbox を見ると、落ちるのは**段の下端（y≈770〜790pt、本文領域の末尾）から次の段へ割れた脚注**である。

```
fn_ch4_s2_a2__n1 の fragments:
  page10 左段 [39.7, 770.7, 286.3, 790.9]   ← ここが PDF に出ない
  page10 右段 [309.0,  25.9, 555.6,  51.1]
```

つまり**内容の種類ではなく、脚注がどの位置に来るか**で起きる。拡張が作る文言の問題ではない。

## 拡張側の扱い

1. G9c で落ちた文書は**出力しない**（崩れた文書をデータセットに入れない）。
2. バッチは、ルール数と seed を変えて組み直す（`batch.RETRIES`）。
   長さが数十字変わると位置が動き、通ることが多い。
3. それでも通らない content は、失敗として原因と再現コマンドを記録する。

## どう直したか（2026-10-03・S10-2）

```css
.footnotes .fn-line { display: grid; grid-template-columns: max-content 1fr; column-gap: 0.6em;
                      break-inside: avoid; }
```

**脚注ブロック全体ではなく、脚注 1 本（`.fn-line`）に効かせる。** 落ちるのは
「1 本が 2 つの段に割れた」場合であり（上の bbox の実測のとおり）、ブロック全体を割らせないと
長い脚注群が丸ごと次の段へ飛んで版面が荒れる。

同じファイルの `.footnotes.remarks`（団体保険の備考欄）が、**同じ失敗の型**に対して
すでに `break-inside: avoid` を使っていた。その先例に合わせた。
