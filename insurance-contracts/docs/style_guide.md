## 7. コンテンツ生成（執筆）

### 7.1 役割分担
- **Python（決定論）**：blueprint からスケルトン生成、番号・参照・目次・ヘッダ経路の導出、lint、描画、検証、自動 QA。
- **Claude Code（執筆）**：スケルトンの穴埋め（条文本文、定義、表の中身、図のノード、脚注、欄外注、alt/facts、執筆 QA）。文章は必ずオリジナル。
- **条文ライブラリ**（§7.6）：定型条（告知義務・通知義務・保険料の払込み・事故時の義務・請求手続・時効・準拠法 等）はジャンルごとに一度オリジナルで書き、パラメータ差替え＋軽い言い換えで再利用する。商品固有の補償条項は文書ごとに書く。

### 7.2 執筆プロトコル（1文書）
```
1. uv run yakkan scaffold --genre auto --content-id auto-0001 --seed 1
     → content/auto-0001/doc.json（meta・骨組みindex）と parts/00_front.json, 10_terms.json, 20_ch1.json … が生成される。
       各 part には blueprint 由来の見出し候補と TODO（必須要素の種類・最小件数・推定字数）が入る。
2. part ごとに執筆（1 part = 1 ターン程度。並列は subagent `author` に part 単位で委譲可）。
   - §7.3 の文体、§7.4 の記法、§4.1 の必須要素、§5 の型に従う。
   - 番号ラベルは書かない。参照は {ref:}、脚注は {fn:n}＋footnotes ブロック。
3. uv run yakkan lint content/auto-0001      # 構造・参照・記法・denylist・推定ページ数
4. uv run yakkan build content/auto-0001     # parts を結合し derived を付与 → content/auto-0001/source.json
5. uv run yakkan render content/auto-0001 --style nl-a4-2col-mincho   # → dataset/auto-0001--nl-a4-2col-mincho/
6. uv run yakkan verify dataset/auto-0001--nl-a4-2col-mincho          # §6.9
7. open dataset/auto-0001--nl-a4-2col-mincho/pages/*.png              # render が既定で出す PNG を全ページ開いて §7.8 チェックリストで確認（/review <doc_id>）
8. uv run yakkan qa dataset/auto-0001--nl-a4-2col-mincho              # 自動QA生成 → Claude が執筆QAを追記 → 再度 qa --validate
9. uv run yakkan manifest update                                     # status: ready
```
差戻しは原則 content（parts）の修正で行い、CSS/テンプレートの修正は全文書に影響するため `docs/decisions.md` に記録して再レンダリングする。

### 7.3 文体ガイド（要点。詳細は docs/style_guide.md へ移す）
**損保約款（nonlife）**
- 主語は「当会社」「保険契約者」「被保険者」「保険金請求権者」。敬体で終始し、条文末は「…支払います。」「…しなければなりません。」「…をいいます。」「…することができます。」「…とします。」。
- 構文パターン（オリジナル例）：
  - 「当会社は、被保険者が保険期間中に急激かつ偶然な外来の事故によって身体に傷害を被った場合に、この約款に従い、保険金を支払います。」
  - 「保険契約者または被保険者は、契約締結後に危険が増加する事実を知ったときは、遅滞なく、その事実を書面等により当会社に知らせなければなりません。」
  - 「ただし、当会社が承認した場合を除きます。」／「…に限ります。」／「…この限りではありません。」
  - 定義：「この約款において『〇〇』とは、…をいいます。」、定義表では文末「…をいいます。」で統一。
  - 免責：「当会社は、次に掲げる事由のいずれかにより生じた損害については、保険金を支払いません。」
  - 算式：文で「次の算式によって算出される額」と述べ、直後に Formula ブロック。
- 脚注は「（*1）　〇〇には、△△を含みます。」の形。欄外注は「〈第３条(2)〉 …のことをいいます。」で対象を明示し、平易な説明文（しおり口調）。

**生保しおり・約款（life）**
- しおり部は読者向けの平易な敬体、Q 見出し（「保険料の払込みが遅れたときはどうなりますか？」）、囲みで「ご注意」。
- 約款部は「会社は、…を支払います。」「保険契約者は、…することができます。」「この場合、…」。用語：責任開始期、保険料払込期月、猶予期間、失効、復活、解約返戻金、契約者貸付、指定代理請求人、給付金。
- 別表は「別表１ 対象となる高度障害状態」のように状態を列挙する表と「（備考）」。

**定款（teikan）**
- 常体。「当会社は、〇〇損害保険株式会社と称し、英文では … と表示する。」「当会社は、次の事業を営むことを目的とする。」「総代会は、毎年〇月に招集する。」。項は「２」「３」で行頭全角。附則に「この定款の変更は、20XX年X月X日から施行する。」。

**共通**
- 一文は長くてよい（実物は 100〜200 字の文が普通）が、係り受けは明確に。二重否定・但し書きの入れ子は 2 段まで。
- 語彙は実務用語を用いる（損害賠償請求権者、先取特権、代位、免責金額、保険価額、協定保険価額、既経過期間、未経過期間、月割、短期率、告知事項、通知義務、重大事由）。造語は避け、架空にするのは固有名詞・数値・商品構成。

### 7.4 語彙・記法規則
- 金額：「1,000万円」「10万円」「無制限」。文書内で表記を統一（`digit_style`）。
- 期日・時刻：「始期日の午後４時」「満期日の午後４時」「午前０時」「翌日から起算して30日以内」。
- 日付：西暦「2026年10月1日」（和暦は variant）。
- 割合：「50％」（全角％、halfwidth variant あり）。
- 列挙の接続：「および」「または」「もしくは」「ならびに」を法令用法で（「A、BおよびC」「AまたはB」「A、BもしくはCまたはD」）。
- 括弧：全角「（）」。英数字は全角/半角を `digit_style` に従う。「ご契約のお車」「ご契約者」の「ご」付き表記はジャンル固有。
- 参照表現は `{ref:}` で生成する。手書きの「第○条」は禁止。

### 7.5 架空化ルール
- 会社名：架空の合成名（例「青葉みなと損害保険株式会社」「常磐ひかり生命保険相互会社」「白鷺海上火災保険株式会社」）。`yakkan/lint/denylist.txt`（実在社名・ブランド・略称：東京海上／日動／日本生命／ニッセイ／損保ジャパン／三井住友海上／あいおいニッセイ同和／第一生命／明治安田／住友生命／かんぽ／ソニー損保／アクサ／チューリッヒ／セゾン／SBI／楽天／イーデザイン／おとなの／東急／共栄／日新／大同／太陽／富国／朝日／オリックス／メットライフ／プルデンシャル／アフラック／JA共済／こくみん共済 等）を完全一致・部分一致で検査し、追加を随時行う。
- 商品名・ペットネーム：架空（「トータルサポート」など実在に近い語は避ける）。
- 連絡先：`0120-000-000` 系のゼロ埋めのみ、URL は `example.jp` 系のみ、メールは `@example.jp`。
- 様式番号・証券番号：明らかな例示（「Ｄ２６１００１」「００００－００００００」）。
- 法令名（保険法、自動車損害賠償保障法、民法、道路交通法）は実在で可。条番号を引くときは正確に（不確かなら条番号を書かない）。
- 奥付の定型文（`meta.disclaimer`、必ず含める）：「本冊子は、文書読取技術の検証を目的として作成された架空の約款です。記載の会社・商品・連絡先は実在しません。」ページごとには入れない（読み取り対象の自然さを損なうため）。

### 7.6 条文ライブラリ（`library/clauses/<genre>/*.json`）
- 1ファイル＝1条（または1節）。`params`（社名、日数、金額、対象物の呼称）と `variants`（言い換え2〜3種）を持つ。
- compose 時に blueprint の指定と seed で選択し、`content/<id>/parts/` にコピーされる（以降は文書固有として編集可）。
- ライブラリ文もオリジナルで書く。実物の定型句を「参考にした」としても、文の写しは不可。

### 7.7 多様性の担保
- 同一ジャンル内で 3 文書以上作る場合、章構成・特約・定義語・数値・図の題材を変える。`yakkan lint --similarity` で既存文書との文単位重複率（n-gram）を出し、30% を超えたら警告。
- スタイルは `styles/*.yaml` のプリセット 7 種以上を用意し、1 content に対し 1〜3 style で描画する。

### 7.8 視覚レビュー・チェックリスト（review で全ページ確認）
- 見出しラベルと文言の位置関係、ぶら下げインデントが揃っているか
- 表：列幅、結合セル、表頭繰返し、段またぎ、はみ出し、罫線
- 図：文字の重なり・切れ、矢印の向き、凡例
- 段組：段の高さ、孤立行、図表の直後の空白
- ヘッダ・フッタ・ページ番号・目次ページ番号
- 記号（❶◆☞）が豆腐になっていないか、ルビ位置
- 「本物らしさ」：情報密度、色数、余白（派手な UI 的装飾は禁止）
