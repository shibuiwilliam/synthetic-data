## A. 正解データの質に直接効くもの

### A1. 条末脚注が段の境界に当たると PDF から落ちる → **現行コードでは再現しない**（2026-09-22 実測）

P5 の執筆担当 5 人が遭遇し、いずれも直前の項に数十字足して回避した
（**内容上の必然性がない加筆が各文書に入っている**）。

`scripts/probe_layout_band.py` で **3 文書・計 55 通り**の配置をずらして測ったが、
**内容欠落（V03／V05）は 1 度も起きなかった**：

| 文書 / style | 試行 | 内容欠落 |
|---|---|---|
| sample_min / nl-a4-2col-mincho（16 字刻み） | 37 | 0 |
| auto-0001 / nl-a4-2col-mincho（35 字刻み） | 6 | 0 |
| quake-0002 / nl-b5-2col-dense（35 字刻み） | 8 | 0 |

現行の 28 データセットでも、脚注 1,114 件のうち **24 件が実際に段・ページをまたいで分割**
されているが、すべて verify を通っている。

**推定される原因**：2026-09-21 に章見出しを `column-span: none` にして
段組の中から span-all 要素を消したこと（同じ根で「後続が黙って消える」不具合も直した）と、
2026-09-22 に `_extend_fragments_to_lines` で fragment が自分の行を覆うようにしたこと。

**方針**：`.footnotes { break-inside: avoid }` は**入れない**。
再現しないものに対して規則を足すと、`figcaption` のときと同じく別の欠落を招く恐れがある
（`docs/decisions.md` 2026-09-22「`figcaption { break-after: avoid }` は採用しない」）。
V03／V05 が安全網として機能しているので、**再発したら probe で帯を測ってから設計する**。

### A5. rowspan がページ／段の境界をまたぐと継続側のセルが空欄になる → **正解は壊れていない**（2026-09-22 実測）

28 データセットを調べた結果：

- **rowspan のセルが複数の fragment に分割された例は 0 件。** 継続側には描かれず、
  `layout` も「1 回だけ描かれた」と記録している。**紙面と正解が一致している**
  （`repeated` は表頭の再掲のための印で、この現象とは別）。
- 見出しが別ページにある本文セルが **35 件**あるが、いずれも
  `derived.tables[].header_path[].row_headers` がその見出しを指している。
  **意味の正解は失われていない。**

読み手（と読み取りモデル）には空欄に見えるが、前ページの見出しを引き継いで読む必要がある
という**正当な読み取り課題**であり、正解はそれを支えている。
回帰テスト：`tests/unit/test_lint.py::test_header_pathはrowspanの見出しを全行で指す`。

## D. その他

### D2. `RenderLayoutError` は「帯」で起きる → **幅を実測した**（2026-09-22）

`scripts/probe_layout_band.py` で測ると、`AssertionError`
（`weasyprint/layout/page.py:717 make_page`）が出るのは**連続した 1 つの帯（48 字幅）だけ**で、
その両側は正常に描けた。「数十字ぶん増減させる」は正しいが、**帯の中で数字を振っても通らない**。
oneday 担当が「どう振っても通らなかった」と報告したのは、帯の中で往復していた可能性が高い。

帯の幅は内容・style によって変わるので、詰まったらこの probe で位置と幅を測るのが早い。
WeasyPrint 側に報告するなら、この probe の出力（帯の位置・幅・落ちる行番号）を添える。

## 着手の順序について

**番号（表N・図N）の振り方を変えるときは、執筆QAの見直しとセットで行うこと。**
執筆QAの問い文は表番号・図番号を本文中に書いていることがある。手順：

1. すべての content の執筆が終わってから着手する
2. 番号を振るコードを直す
3. `yakkan batch specs/batch_v1.yaml` で全文書を作り直す
4. `content/*/qa_authored.json` を grep して「表N」「図N」「別表N」を含む問いを洗い出し、
   新しい番号に直すか、番号を使わない書き方に変える
5. `yakkan qa` を全データセットで回して L14 が通ることを確認する

自動QAは番号を `derived.tables[].caption_label` から取るので自動で追従する。
**手で書いた問いだけが追従しない。**
