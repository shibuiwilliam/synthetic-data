## A. 正解データの質に直接効くもの

### A1. 条末脚注が段の境界に当たると PDF から落ちる → **現行コードでは再現しない**（2026-09-22 実測）

P5 の執筆担当 5 人が遭遇し、いずれも直前の項に数十字足して回避した
（**内容上の必然性がない加筆が各文書に入っている**）。

`scripts/probe_layout_band.py` で **3 文書・計 55 通り**の配置をずらして測ったが、
**内容欠落（V03／V05）は 1 度も起きなかった**：

| 文書 / style | 試行 | 内容欠落 |
|---|---|---|
| sample_min / nl-a4-2col-mincho（16 字刻み） | 37 | 0 |
| auto-0001 / nl-a4-2col-mincho（35 字刻み） | 6 | 0 |
| quake-0002 / nl-b5-2col-dense（35 字刻み） | 8 | 0 |

現行の 28 データセットでも、脚注 1,114 件のうち **24 件が実際に段・ページをまたいで分割**
されているが、すべて verify を通っている。

**推定される原因**：2026-09-21 に章見出しを `column-span: none` にして
段組の中から span-all 要素を消したこと（同じ根で「後続が黙って消える」不具合も直した）と、
2026-09-22 に `_extend_fragments_to_lines` で fragment が自分の行を覆うようにしたこと。

**方針**：`.footnotes { break-inside: avoid }` は**入れない**。
再現しないものに対して規則を足すと、`figcaption` のときと同じく別の欠落を招く恐れがある
（`docs/decisions.md` 2026-09-22「`figcaption { break-after: avoid }` は採用しない」）。
V03／V05 が安全網として機能しているので、**再発したら probe で帯を測ってから設計する**。

### A2. 図と算式の中で `{const:}` `{term:}` `{ref:}` が解決されない

図は自前で SVG を組み立て、`Formula` の box も RichText を受け付けないため、
トークンを書くと**そのまま PDF に描かれる**（auto-0002 の凡例で実際に発生）。

- 暫定：lint L06 が「図の中にトークンがあったら error」で弾き、平文で書かせている（2026-09-22）。
- **そのため定数を変えても図が追従せず、取り残しが実際に複数回起きた**
  （quake の 30日/20日、health-0002 の 75日、life-0003 の 200万円）。
- 本筋：build が `derived.figures[fig_id].resolved_labels`（node_id → 解決後の文字列）を作り、
  描画側がそれを使う。`source` の diagram は執筆物のまま残せるし、QA も解決後の文字列を使える。
  `Formula` も同じ扱いにする。

### A3. `{ref:}` が表・図・別表を参照できない

`{ref:tbl_coverage}` は L01 で落ちる。`build` は `derived.tables[].caption_label` に
「表N」を持っているのに、ref 解決側が見ていない。

- 「表２に掲げる額の２分の１」と書けないため、oneday は `{ref:ch1_a4|short}` で代替した。
- 別表は `{ref:app1}` で参照できる（ノードなので）。表・図だけが参照できない。
- crossref QA の材料としても表・図への参照は欲しい。

### A4. 特約が普通保険約款の通し章番号になる（7 ジャンル中 5 ジャンルで発生）

`Node.kind` に特約用の区分が無く、特約を `chapter` として body に置くため
「第５章 携行品損害補償特約」と普通約款の続き番号になる。そのうえで
「普通保険約款を準用します」と書くと**自己言及**になる。

- 現状の作法：準用文を「第1章から第N章までの規定を準用します」と書いて回避している。
- 本筋：`kind: "rider"` を models に追加し、numbering で「特約第○条」の独立体系にして、
  目次でも本文と別建てにする。読替え表の左列が「第3章第6条(2)」と章冠付きで出るのも直る。
- 影響が大きいので P6 送りの判断もありうる。

### A5. rowspan がページ／段の境界をまたぐと継続側のセルが空欄になる → **正解は壊れていない**（2026-09-22 実測）

28 データセットを調べた結果：

- **rowspan のセルが複数の fragment に分割された例は 0 件。** 継続側には描かれず、
  `layout` も「1 回だけ描かれた」と記録している。**紙面と正解が一致している**
  （`repeated` は表頭の再掲のための印で、この現象とは別）。
- 見出しが別ページにある本文セルが **35 件**あるが、いずれも
  `derived.tables[].header_path[].row_headers` がその見出しを指している。
  **意味の正解は失われていない。**

読み手（と読み取りモデル）には空欄に見えるが、前ページの見出しを引き継いで読む必要がある
という**正当な読み取り課題**であり、正解はそれを支えている。
回帰テスト：`tests/unit/test_lint.py::test_header_pathはrowspanの見出しを全行で指す`。

## B. 体裁（読者に見えるが、正解は壊れていない）

### B1. 表題（figcaption）と表本体がページ／段で分離する

`break-after: avoid` は本文欠落を誘発するため**採用できない**（実測済み）。別手段を探す。

### B2. 表紙にヘッダ・フッタ・ページ番号が出る

`@page :first` で `@top-left` / `@bottom-center` / `@bottom-right` を空にする。
実物の約款冊子の表紙にページ番号は入らない。`layout.json` の `pages[0].header/footer` が
null になるので、正解としてもより正確になる。

### B3. フッタのページ番号が半角

`counter(page)` なので `digit_style: fullwidth` の文書と不整合。
実物の日本語冊子もページ番号は半角が多いので、**意図的に半角と決めるなら decisions に記録する**。

### B4. `page_break` ブロックが未実装

`html.py` が空文字を返している。スキーマは宣言しているので実装する。
別表がページ境界で 1〜2 行だけ残る問題の制御手段になる。

### B5. timeline の軸目盛ラベルが 5 文字以上で viewBox から切れる

両端にパディングを入れる。執筆側は 4 文字に切り詰めて回避している。

### B6. matrix 図の列幅が固定 62px

列見出しを短縮せざるを得ない。ラベル長に応じて広げる。

## C. teikan（定款）固有

### C1. 号の記号が ①②③（損保約款流）

定款の慣行は `(1)(2)(3)` または漢数字。`yakkan/build.py` の `enumeration_labels()` が
`circled()` を無条件に呼ぶため scheme に関係なく丸数字になる。
`_label_teikan` の item は既に `（１）` を返すので、`label_for(ctx, "item", n, ...)` 経由にすれば揃う。

### C2. `{ref:}` に章の冠が付く

条が全編通し番号（`CONTINUOUS_ARTICLE_SCHEMES`）なので「第３章第１４条」の章プレフィックスは不要。
同一章内参照（「第１４条（決議）」）と挙動も不統一。

### C3. 附則の見出し形式

`_label_appendix_inner` が `appendix_section` に「第１」、paragraph に「１．」を振る。
定款の附則は項番号「１」「２」で起こすのが通例。

### C4. 附則内参照が「第３」とだけ解決される

実物なら「附則第３」と書くところ。

### D2. `RenderLayoutError` は「帯」で起きる → **幅を実測した**（2026-09-22）

`scripts/probe_layout_band.py` で測ると、`AssertionError`
（`weasyprint/layout/page.py:717 make_page`）が出るのは**連続した 1 つの帯（48 字幅）だけ**で、
その両側は正常に描けた。「数十字ぶん増減させる」は正しいが、**帯の中で数字を振っても通らない**。
oneday 担当が「どう振っても通らなかった」と報告したのは、帯の中で往復していた可能性が高い。

帯の幅は内容・style によって変わるので、詰まったらこの probe で位置と幅を測るのが早い。
WeasyPrint 側に報告するなら、この probe の出力（帯の位置・幅・落ちる行番号）を添える。

### D3. QA の 10 種別に「場面適用型」が無い

「◯◯の場合、保険金は支払われますか」という問いは答えが算出値・要約になるため、
`extract` 系の包含検査を通らず `table_reason` に寄せるしかない。
**QA 執筆担当 3 人が独立に同じ指摘をした。** 種別を足すか、包含検査の対象外の型を用意する。

### D4. `blueprints/*.yaml` の `required` が実態に合わない場合がある

life は `surgery_schedule` を要求するため、こども保険（life-0003）でも
「手術・治療」系の表を 1 つ置かざるを得なかった。
teikan は表 4 点以上を要求するが、実物の定款に一覧表が 4 つ載るのは稀。

### D5. `blueprints/travel.yaml` の appendices の要件が `all_requirements()` に入っていない

L04 は「rate 5行以上の表が文書のどこかに1つ」しか見ておらず、別表の要件が実質検査されていない。

## 着手の順序について

**番号（表N・図N）の振り方を変えるときは、執筆QAの見直しとセットで行うこと。**
執筆QAの問い文は表番号・図番号を本文中に書いていることがある。手順：

1. すべての content の執筆が終わってから着手する
2. 番号を振るコードを直す
3. `yakkan batch specs/batch_v1.yaml` で全文書を作り直す
4. `content/*/qa_authored.json` を grep して「表N」「図N」「別表N」を含む問いを洗い出し、
   新しい番号に直すか、番号を使わない書き方に変える
5. `yakkan qa` を全データセットで回して L14 が通ることを確認する

自動QAは番号を `derived.tables[].caption_label` から取るので自動で追従する。
**手で書いた問いだけが追従しない。**
