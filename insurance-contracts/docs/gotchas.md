## WeasyPrint / macOS：`OSError: cannot load library 'libgobject-2.0-0'`

- 症状：`uv run python -c "import weasyprint"` が dlopen 失敗で落ちる。Pango 自体は brew で導入済みでも起きる。
- 原因：Homebrew の dylib は `/opt/homebrew/lib` にあるが、dyld の既定検索パスに含まれない。
- 回避策：`DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib` を付けて実行する。
  - `Makefile` が自動で export する（`make check` / `make smoke` はそのまま通る）。
  - Claude Code のセッションでは `.claude/settings.json` の `env` で渡している。
  - 素の `uv run yakkan doctor` を直接叩くときは自分で付ける。付け忘れても `doctor` は NG 行とヒントを出す。
- 確認日：2026-09-21（WeasyPrint 70.0 / Pango 1.56.4）。

## WeasyPrint：box ツリーから element id → bbox が取れる（**最重要 probe・成功**）

CLAUDE.md §14 の筆頭リスク。`yakkan/layout/extract.py` に実装と所見を記載。

- `document.pages[i]._page_box` は私的 API だが **70.0 で健在**。`box.element.get("id")` で HTML の id が取れる。
- 座標は `border_box_x() / border_box_y()`、**寸法は `border_width() / border_height()`**。
  `border_box_width()` は存在しない（`AttributeError: Did you mean: border_top_width?`）。ここを間違えやすい。
- 単位は CSS px。pt へは ×0.75。原点は左上。
- **2 段組で分割された要素は同じ id の box が複数現れる**（§5.7 の `fragments` がそのまま取れる）。
- `LineBox` / `TextBox` が行単位の bbox を持つので `text_lines` も同じ走査で取れる。
- smoke（1 ページ）で 122 断片を取得。`write_pdf` の **前** に同じ document から取ること（§6.8-5）。

## HTML：`body` の既定マージン 8px が本文領域を削る

- 症状：`@page { margin: 14mm }` のつもりが、本文の実効左右マージンが 6pt ずつ広くなる（本文幅 515.9pt → 503.9pt）。
- 原因：`body` の既定マージン 8px（= 6pt）。box ツリーの実測幅が計算値と合わないことで気づいた。
- 回避策：スタイルシートの先頭で `body { margin: 0 }`。P2 のテンプレート CSS にも必ず入れる。
- 確認日：2026-09-21。

## SVG 内の日本語テキストは PDF のテキスト層に載る

- `<text>` で書いた日本語は pdfplumber で抽出できる（smoke の「事故の発生」「当会社へ通知」「受付」で確認）。
- **影響**：§6.9 の往復比較で図のラベルが本文に混ざる。`layout.json` 側で `region: "figure"` として区別し、
  本文テキストの比較からは除外する必要がある（ヘッダ・フッタ・繰り返し表頭と同じ扱い）。
- SVG の `<text>` には `font-family` / `font-size` を必ず属性で明示する（省略するとフォールバックで幅がずれる）。

## pdfplumber：`extract_text()` は原文にない空白を入れる

- 症状：`extract_text()` は字間から単語境界を推定して ASCII 空白を挿入するため、原文と一致しない。
  2 段組では左右の段の行が同じ y で交互に連結される。
- 回避策：`page.chars` から自分で行を組み立てる。**U+3000 などの原文の空白はそのまま残る**（実測）。
  正規化ルールは `yakkan/verify/normalize.py` の docstring に明文化した（空白のみ無視、全角半角は区別）。
- 確認日：2026-09-21。

## 2 段組の読み順：文字座標だけでは段またぎ要素を判定できない

- 症状：段またぎのキャプション（例「表１　…」）は描画幅が段幅に満たないため、
  左段の行と区別できない。誤って左段の流れに混ざると、段をまたぐ段落の本文が途中で割れる。
- 原因：判定に必要なのは **要素の box 幅**であって、描画された文字の広がりではない。
- 回避策：box ツリー（`yakkan.layout.extract.span_bands`）から段またぎ要素の y 範囲を渡す。
  `yakkan/verify/normalize.read_lines(span_bands=...)` がそれを使う。P2 では `layout.json` が正式な読み順を持つ。
- 併せて：右段の 1 文字目は段間の右端に **ぴたりと接する** ため、段間の判定には 0.5pt 程度の許容が要る
  （浮動小数の誤差で「段間に食い込んでいる」と誤判定した）。
- 確認日：2026-09-21。

## macOS：`ctypes.util.find_library("ffi")` は None を返す

- 症状：libffi の存在確認に `find_library` を使うと、動いているのに「未検出」になる。

- 原因：親 `synthetic-data/.gitignore` に Python 汎用の `parts/`（setuptools 由来）がある。`lib/` `build/` 等も同種。

## WeasyPrint：`float: footnote` は効かない／`<ruby>` はルビにならない

## box ツリーの y と pdfplumber の y は一致しない（IoU 判定は使えない）

- 実測：x は 0.00pt 一致。y は BlockBox の上端が文字の上端より **4.93pt** 上（行の余白ぶん）、

- 置き換え：**box ツリーの bbox が pdfplumber の文字群の bbox を内包するか**（許容 1pt）で判定する。
- 確認日：2026-09-21。

## ヘッダ・フッタは y 座標では判定できない（MarginBox を見る）

- 症状：本文の 1 行目がヘッダとして分類され、`layout.pages[].header` に本文が混ざる。
- 原因：`@page` の上マージンの下端と本文領域の上端が同じ y（16mm = 45.35pt）から始まるため。
- 回避策：box ツリーの **`MarginBox` の `at_keyword`**（`@top-left` / `@bottom-center` …）で領域を決める。

## 脚注・欄外注はブロックの並び順ではなく「役割」で位置を決める

- 症状：条の直下に置いた `footnotes` / `margin_note` が、項（子ノード）より **前** に描画される。
- 原因：`node.blocks` を子ノードより先に描いていた。条ノードでは blocks が条末の付属物にあたる。
- 回避策：`footnotes` と `box[style=margin_note]` だけを「条末に置くブロック」として最後に回す
  （`yakkan/render/html.py` の `_is_trailing`）。項に付く列挙表などはその場に置く。
- 確認日：2026-09-21。

## インライン SVG の中身は box ツリーに出ない（テキスト層には出る）

- 実測：`<svg>` は ReplacedBox として置かれ、その中の `<text>` は LineBox / TextBox にならない。
  そのため `layout.json` の `text_lines` に figure 領域の行は **1 本も出ない**。
- 一方で PDF のテキスト層には出る（pdfplumber で抽出できる）。
- 影響と対処：

  - 図の正解は `layout.figures[].nodes`（座標）と `alt` / `facts`（意味）が担う。
  - verify V10 が「ノード座標が空でないこと」と「ラベルが PDF から読めること」を検査する。
- 確認日：2026-09-21（WeasyPrint 70.0）。

## WeasyPrint：段組の中に「1 ページを超える段またぎ要素」を置くと、以降の内容が消える

- 症状：目次（`column-span: all`）が長くなると、**本文の先頭の数章がまるごと PDF に出ない**。
  しかもページ数が **減る**（6 → 5）。verify の V05（全要素が fragment を持つ）だけが気づける。
- 再現：`column-fill: auto` の段組コンテナの中に、`column-span: all` で 1 ページを超える高さの
  要素（目次 45 行以上）を置く。40 行では起きず、45 行から起きる。
- 原因の切り分け：目次を `<nav>` ごと消すと解消。段数・`column-fill`・`leader()`・`target-counter`・
  `break-inside` を個別に外しても解消しない。**段組コンテナの中にあること**が条件。
- 回避策：**長くなりうる段またぎ要素は段組コンテナの外に置く。** 目次はテンプレートで `.cols` の外に出した。
  段またぎの表（`span_columns`）も 1 ページを超えそうなら同様に扱う。
- 安全網：verify V05。これが無いと黙って内容が消える。
- 確認日：2026-09-21（WeasyPrint 70.0）。

## WeasyPrint：ページ分割の内部アサーションで落ちることがある

- 症状：`assert not page_is_empty`（`weasyprint/layout/page.py`）で `AssertionError`。

  **自動でレイアウトをずらす回避はしない**（bbox とページ番号が変わり、正解データが壊れるため）。

## WeasyPrint：`target-counter` の目次ページ番号が収束しない → 2 パス描画にした

- 症状：目次に印字されたページ番号が実ページと食い違う（5 と印字されているが実際は 8）。
  目次が長いほど起きやすい。`leader()` や行折返しを外しても直らない。
- 原因：`target-counter` はページ番号が確定するまで再レイアウトを繰り返すが、
  目次の高さが番号によって変わるため振動し、打ち切られた時点の値が残る。
- 対処：**2 パス描画**にした（`yakkan/render/weasy.py`）。
  1 パス目は `target-counter` で描いて実ページを測り、2 パス目でその値を**文字として**目次に埋める
  （`a.fixed::after { content: leader('.') }` で target-counter を止める）。
  2 パス目で見出しが動いた場合だけ、もう一度だけ測り直す。
- 決定論は保たれる（同じ入力 → 同じ出力）。verify V04 が印字と実ページの一致を検査する。
- 確認日：2026-09-21。

## ぶら下げ段落（CSS grid）は `break-inside: avoid` が無いと段またぎで壊れる

- 症状：2 段組で `.para`（`display: grid` のぶら下げ）が段の境界で分割されると、
  **右段の 1 行目が本文領域より上（ヘッダ帯）に描かれる**。実測で y=35pt（本文領域は 45.35pt から）。
- 検出：verify V03 の往復比較。ヘッダ帯の文字を除外して比べたら、本文が丸ごと消えているように見えた。
- 対処：`.para { break-inside: avoid; }`。副作用として、P2 で記録した
  「ラベルだけが前の段に取り残される」問題も解消した。
- 代替案（`padding-left` ＋ 負の `text-indent`）も試したが、別の往復不一致が出たため採らなかった。
- 制約：1 項が段の高さを超えると配置できなくなる。**1 項は長くても段の半分まで**に収める。
- 確認日：2026-09-21。

## 目次の突合は id で行う（見出し文言は一意ではない）

- 症状：「第1条（この条項の補償内容）」が 3 つの章に現れ、verify が別の章の目次行と突き合わせて誤検出した。

## ラベル欄の固定幅は壊れる（脚注マーカー・項ラベル）

  ページ下部で始まった章の名前がそのページのヘッダに出る（＝1ページ先行して見える）。

## `RenderLayoutError` は「帯」で起きる（幅を実測した）

- `scripts/probe_layout_band.py` で sample_min の本文を 16 字ずつ 37 段階に伸ばして測ると、
  `AssertionError`（`weasyprint/layout/page.py:717 make_page`）が出るのは
  **連続した 1 つの帯（48 字幅）だけ**で、その両側は正常に描けた。
- つまり「数十字ぶん増減させる」は正しいが、**帯の中で数字を振っても通らない**。
  帯をまたぐだけの量（この例では 48 字超）を動かす必要がある。
  oneday の担当が「どう振っても通らなかった」と報告したのは、帯の中で往復していた可能性が高い。
- 帯の幅は内容・style によって変わる。詰まったらこの probe で帯の位置と幅を測るのが早い。
- 対処の順序：(1) 字数を増減、(2) 項の分け方を変える、(3) 別の style で描く。
  **自動でレイアウトをずらす回避は入れない**（bbox とページ番号が変わり正解が壊れる）。
- 確認日：2026-09-21。

## 段またぎ要素はページ境界で「それ以降の内容を全部」捨てる（最重要）

- 再現（2026-09-21、auto-0001）：`ch3_a5_p1` に **60字足すだけ**で 16 ページ → **11 ページ**。
  第5章（基本条項）・特約3本・別表2本・奥付がすべて PDF から消える。lint は通り、render は成功したと報告する。
- さらに悪いのは、**通っていた16ページ版が「章見出し帯がページ最下部にぎりぎり収まっていたから」通っていた**点。
  前方の字数がわずかに増えれば同じ事故が起きる状態で、それを知らずに「通った」と判断していた。
- 原因：`column-span: all` の要素（章見出し帯・`span_columns: true` の表）が段組の残り高さに収まらないとき、
  WeasyPrint はエラーを出さずに後続を破棄する。
- 対処（2段構え）：
  1. **章見出し・別表見出しを `column-span: none` にした**（段内に戻すとこの失敗モードが構造的に消える）
  2. **`render` が内容欠落を検出したら止まる**ようにした（`_assert_nothing_dropped`）
- 教訓：**この renderer に対しては「レンダリングが成功した」は「内容が全部載った」を意味しない。**
  ページ数と lint だけで判断してはいけない。
- 確認日：2026-09-21。
