## R1 検索 qrels の部分適合が薄い

### 実測

| クエリ種別 | grade 2 | grade 1 |
|---|---|---|
| heading | 640 | **9** |
| term | 352 | **0** |
| scoped | 78 | **0** |
| qa | 1,267 | 308 |

**適合が 1 件だけのクエリが 1,071 / 1,549（69%）。** これでは nDCG がほぼ二値になり、
順位の良し悪しを測る分解能が出ない。ランク学習の学習信号としても弱い。

### 原因（2 つ）

1. **citation の突合が完全一致になっている**（バグ）。
   表・図のパッセージの `citation` は**導入文の項**（「第1章 第1条 (1)」）から取るが、
   条のパッセージは「第1章 第1条」。前方一致で見るべきところを完全一致で見ていたため、
   369 件の表・図のうち条と結びついたのは **15 件だけ**だった。
2. **grade 1 の供給源が「同じ条の別の項」しかない。** `derived` には他にも
   機械的に導ける関係があるのに使っていない。

### 対処（**関係は derived に実在するものだけを使う。適合度を捏造しない**）

| クエリ種別 | grade 1 にするもの | 根拠 |
|---|---|---|
| term | その語を `{term:}` で実際に使っている要素を含むパッセージ | `derived.term_uses` |
| term | その語を行見出しに持つ定義表のパッセージ | 定義表のセル |
| heading | その条に属する表・図（**前方一致で直す**） | `citation` の前方一致 |
| heading | その条を `{ref:}` で参照している条 | `derived.refs`（to_id が当該条） |
| scoped | その文書の、その条に属する表・図 | 同上 |
| qa | evidence の条を `{ref:}` で参照している条 | `derived.refs` |

grade 1 が増えすぎると評価が緩くなるので、**1 クエリあたり grade 1 は 20 件まで**に切る
（`citation` の近い順）。

## R2 新ジャンルの content が各 1 本

既存 7 ジャンルは 3 content ずつ（seed 1〜3）あるのに、2026-09-22 に足した
`golf` / `group` / `jyusetsu` は 1 本ずつしかない。**ジャンル間でデータ量が 3 倍違う**ので、
ジャンル別の評価をすると新ジャンルだけ統計が薄くなる。

対処：各ジャンル 2 本目・3 本目を執筆する（計 6 文書）。
`variants` を変えて題材・数値・図表を変え、`lint --similarity`（L15）で
同一ジャンル内の重複率が 30% を超えないことを確かめる。

## R3 `answer.json` の二重持ち

### 実測（34 文書の合計）

| ファイル | 合計 |
|---|---|
| `answer.json` | **42MB** |
| `source.json` | 16MB |
| `layout.json` | 20MB |
| `pages/*.png` | 213MB |
| 全体 | 335MB |

`answer.json` は `source` と `layout` を**丸ごと内包**しているので、**36MB が重複**している。
バイト数だけなら PNG が支配的だが、問題は容量よりも
**「同じ正解が 3 か所にあり、どれが正か利用者に分からない」**こと。

### 対処

`answer.json` からは `source` / `layout` を**落とす**（同じディレクトリに実体があるので参照で足りる）。
代わりに `yakkan.answer.load_answer(dataset_dir)` を用意し、3 ファイルを読んで
`Answer` を組み立てる。**メモリ上の `Answer` の形は変えない**ので、
`qa` / `eval` / `export` のコードは読み込み方だけ差し替えれば済む。

## R4 階層つき表番号（表1-1）

参考 #14（団体保険の加入のしおり）は **`（表1-1）` `（表3-2）` のように章番号を含む表番号**を使う。
現行は文書内通し番号「表1」「表2」だけで、この形を 1 文書も再現できていない。
読み取りとしては「表番号から章を復元できるか」という別の課題になる。

対処：`meta.caption_numbering: "flat" | "chapter"` を足し、`chapter` のときは
「表<章番号>-<章内の連番>」にする。blueprint から scaffold が写す。`group` の 2 本目で使う。

## R6 `calibrate_styles.py` の 2 段組

`measure()` は「1 ページ目に実際に描かれた文字数」を数えるが、版面が違う 2 段組の style で

影響は lint L09（推定ページ数）の warn だけで、データセットの正しさには効かない。

## 実施の記録（2026-09-22）

| # | 結果 |
|---|---|
| R1 | 表・図の citation を**前方一致**で突合するよう直し（369 件中 15 件 → 354 件が条と結びついた）、`derived.term_uses` と `derived.refs` から grade 1 を導いた。**grade 1 が 317 → 3,805、適合が 1 件だけのクエリが 69% → 32%、1 クエリあたりの適合数の中央値が 1 → 2。** 満点の並びでの nDCG は 1.0 のまま |
| R2 | golf / group / jyusetsu の 2〜3 本目を執筆（計 6 文書）。**40 データセット・543 ページ・1,802 問**。L15 の重複率は全ジャンルで 30% 未満（golf-0003 は 34%、group-0003 は 39%、jyusetsu-0002 は 36% から書き直した） |
| R3 | `answer.json` から `source` / `layout` を外し、`load_answer()` で 3 ファイルを結合するようにした。**42MB → 5.3MB**（1 文書 1.7MB → 184KB） |
| R4 | `meta.caption_numbering: flat \| chapter` を足した。`chapter` は「表1-1」。`group-0002` が参考 #14 の体裁で使っている |
| R5 | `dataset-v2` を打った（`dataset-v1` は履歴として残す） |
| R6 | **原因は `.para { break-inside: avoid }`**（段またぎで grid が壊れるため必須）。段落が分割されないため 1 ページの容量が段落単位で量子化され、較正用の地の文（1 段落 ≒ 54 字＝2 行）では分解能が足りず、別の版面が同じ段落数に着地していた。較正を**実コーパス基準**に変え、L09 の平均絶対誤差 3.8% → 2.3%、最大 15.3% → 12.3% |

**自己評価**：40 文書すべてで `yakkan eval --oracle` が全 13 指標満点。
検索も満点の並びで nDCG@1/5/10 = 1.0。`make check` 緑。

### R4 の既知の制限

`caption_numbering: chapter` のとき、章の外（別表・前付け）の表・図は通し番号のままなので、
同じ文書に「表1-1」と「表1」が並ぶ。読み手は書式で区別できるし `caption_label` も一意なので
実害は無いが、`別表1` 側に番号を振らない・別の接頭辞にするなどの案は見送った（実物に根拠が無いため）。
